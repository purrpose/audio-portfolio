# Purpose Music — личный аудиоархив

Портфолио Вячеслава Синицына. Обычные HTML/CSS/JS, без сборки и зависимостей во время работы. Интерфейс на EN/RU; язык сохраняется локально, если браузер разрешает localStorage.

Порядок: первый экран → шоурил → музыка → SFX → игры → обо мне → навыки → контакты. Courier New — единственный шрифт интерфейса; все шрифты системные. Логотип P сохранён в SVG. Оформление напоминает студийный журнал: тёмная страница, жёлто-зелёные заголовки и элементы управления, линии и колонки метаданных. Декоративной нумерации нет.

## Локальный просмотр

```powershell
node docs/serve-preview.cjs
```

Откройте `http://127.0.0.1:4173`. Этот сервер поддерживает HTTP byte ranges для перемотки WAV/MP3; обычный `python -m http.server` их не поддерживает. Проверяйте видео через HTTP(S): при открытии `index.html` через `file://` YouTube не получает необходимый Referer.

## Где редактировать

| Файл | Содержимое |
| --- | --- |
| `index.html` | Порядок и разметка разделов |
| `style.css` | Courier New, цвета, линии, отступы, адаптивная вёрстка |
| `script.js` | Генерация каталога, меню, переводы, плееры и копирование Discord |
| `portfolio-data.js` | Все проекты, треки, SFX, контакты и тексты |

В `portfolio-data.js` каждый объект массива отделяется запятой. У новых объектов задавайте уникальный `id`. Названия файлов и регистр в путях должны совпадать с файлами на диске.

## Медиа: папки и имена

| Материал | Путь | Поле в данных |
| --- | --- | --- |
| Новый локальный музыкальный трек | `assets/audio/music/my-new-track.mp3` | `tracks[].src` |
| Новый SFX | `assets/audio/sfx/my-new-sound.ogg` | `sfx[].src` |
| Локальный шоурил | `assets/video/showreel.mp4` или `assets/video/showreel.webm` | `showreelUrl` |
| Обложка новой игры | `assets/images/my-new-game.png` | `projects[].image` |

В `assets/audio/sfx/` добавлены пять реальных эффектов WAV/MP3. Четыре музыкальных трека и шоурил работают по существующим внешним ссылкам. Пути для новой музыки, видео и обложек в таблице — примеры.

## Добавить музыку

Добавьте объект в массив `tracks`:

```js
{
  "id": "my-new-track",
  "title": "Название вашего трека",
  "category": { "en": "Your actual category", "ru": "Ваша категория" },
  "src": "assets/audio/music/my-new-track.mp3"
}
```

Для SoundCloud вместо `src` укажите `url` с настоящей ссылкой на отдельный трек. Если известна точная длительность, можно добавить `duration` в секундах; иначе время отображается как неизвестное. Для локального файла длительность всегда берётся из самого аудио. Если указаны и `src`, и `url`, используется локальный плеер, а ссылка SoundCloud остаётся доступной.

Не требуется добавлять обложку: музыка оформлена как трек-лист. Порядок записей определяется их позицией в массиве.

## Добавить SFX

В `sfx` настроены Sniper Rifle, Phantom, Rusty Gate, Siren и Despair. Пока `src` пустой, кнопка показывает «Ожидание» и отключена. Аудиоэлемент не создаётся, запросов к отсутствующим файлам нет, длительность не выдумывается.

Текущие пути к эффектам:

```text
assets/audio/sfx/sniper_shot.wav
assets/audio/sfx/phantom.mp3
assets/audio/sfx/gate.wav
assets/audio/sfx/siren.wav
assets/audio/sfx/despair (mastered).mp3
```

В `src` используйте прямые слеши `/`, даже на Windows: обратные слеши `\` внутри JS-строк искажают путь. ID можно менять: они должны оставаться уникальными, код не привязан к конкретным названиям.

Для замены эффекта положите файл в папку, заполните соответствующий `src` и замените `title`/`category` на реальные название и тип звука. Можно переименовать файлы или использовать MP3/WAV — главное, чтобы путь совпадал.

Чтобы добавить ещё один звук, добавьте объект в `sfx`:

```js
{
  "id": "my-new-sound",
  "title": "Название вашего звука",
  "category": { "en": "UI / Interaction", "ru": "Интерфейс / Взаимодействие" },
  "src": "assets/audio/sfx/my-new-sound.ogg"
}
```

Плеер включается автоматически. Есть play/pause, время, прогресс, перемотка, повторная попытка после ошибки и остановка предыдущего источника. Enter/пробел нажимают кнопку; стрелки, Home и End управляют перемоткой. Локальное аудио загружает только метаданные до нажатия воспроизведения. Для перемотки хостинг должен поддерживать корректный MIME-тип и HTTP byte ranges.

## Добавить игру

Добавьте обложку и объект в массив `projects`:

```js
{
  "id": "my-new-game",
  "title": "Название игры",
  "image": "assets/images/my-new-game.png",
  "url": "https://your-studio.itch.io/your-game",
  "platform": "itch.io",
  "role": "composerSound",
  "type": "GAME",
  "description": {
    "en": "A short factual note about your audio contribution.",
    "ru": "Коротко и по фактам: что вы сделали для игры."
  },
  "listen": "my-new-track"
}
```

Замените пример на реальные данные. `role: "composerSound"` переводится как «Композитор / Саунд-дизайнер», `"composer"` — «Композитор». Для другой роли добавьте ключ в `text.en`/`text.ru` или используйте буквальную строку. Аналогично работает `type`: `"jam"` — Siberian Game Jam, `"inDevelopment"` — в разработке; используйте их только для соответствующих проектов.

`listen` необязателен и должен совпадать с `id` реального трека. `platform: "Steam"` меняет подпись внешней ссылки. `width`/`height` можно указать по фактическим размерам обложки, `pixelArt: true` — для пиксель-арта. Изображение показывается целиком. При пустом `image` используется текстовая обложка. Стороны разворотов чередуются автоматически.

## Заменить шоурил

Существующая ссылка: `https://youtu.be/1CR6B8WtWFo`. Для своего локального видео поменяйте три поля в `portfolio-data.js`:

```js
"showreelUrl": "assets/video/showreel.mp4",
"showreelLabel": "SHOWREEL",
"showreelDuration": null
```

При известной точной длительности вместо `null` можно указать число секунд. Текущие `110.041` относятся только к существующему шоурилу. Поддерживаются YouTube watch/share/embed, прямые MP4/WebM и ссылки на внешние страницы. Видео загружается по нажатию на превью с крупной кнопкой WATCH THE REEL; отдельной кнопки Open video нет. Для внешней страницы само превью работает как ссылка. Прямое видео получает стандартные видеоконтролы; локальное аудио всегда использует собственный плеер.

## Изменить Skills / Навыки

В `portfolio-data.js` найдите `text.en` и `text.ru`. Ключ `skills` задаёт название раздела, `soundSkills`, `musicSkills`, `technicalSkills` — содержимое трёх колонок. Внутри строки `\n` начинает новую строку. Заголовки колонок: `soundDesignCaps`, `musicCaps`, `technicalCaps`; строка программ внизу — `tools`. Меняйте обе локализации. Разметка раздела находится в `index.html`, секция `id="skills"`; оформление — `.skills` в `style.css`.

`docs/source-inventory.json` — эталон для проверок, сайт не читает из него данные. Названия звуков и пути нужно менять в `portfolio-data.js`, массив `sfx`: `title` — название, `src` — путь к файлу, `category.en` / `category.ru` — категория.

## Контакты и язык

`contacts.email` — адрес с префиксом `mailto:`; `contacts.discord` — ник для копирования. Публичной персональной Discord-ссылки в исходном проекте нет; старый адрес главной страницы хранится только как `legacyDiscord`. Форма обратной связи и выдуманная ссылка на профиль не добавлялись.

Биография находится в `about.en`/`about.ru`, подписи интерфейса — в `text.en`/`text.ru`. Переключение языка не сбрасывает текущий плеер. При запуске другого источника предыдущий внешний виджет закрывается, локальное аудио ставится на паузу. Повторное открытие внешнего виджета начинает новый сеанс.

## Cloudflare / публикация

Сохраняется текущая схема обычного статического сайта из корня. Серверный JS, сборка, npm-зависимости и изменение маршрутов не требуются. Конфигурационных файлов Wrangler/Workers/Pages и CI в исходном проекте нет; настройки в аккаунте Cloudflare из этого checkout проверить нельзя.

Для загрузки нужны `index.html`, `style.css`, `script.js`, `portfolio-data.js`, `assets/` и исходная фотография `.jpg` в корне. `docs/` и README — документация и инструменты разработки, при ручной публикации их можно исключить. Текущую папку публикации и build command в Cloudflare менять не нужно. Публикация в аккаунт не выполнялась.

Удалены неиспользуемые IBM Plex WOFF2, CSS/лицензия этих шрифтов, скрипт их загрузки и устаревшая архивная HTML-страница. Все пять оригинальных обложек и фотография сохранены без изменений. Контрольные суммы, ссылки и роли до редизайна записаны в `docs/source-inventory.json`.

## Проверки

Для проверок используются Playwright вне репозитория и установленный Microsoft Edge. Сначала запустите локальный сервер, затем:

```powershell
npm install --prefix "$env:LOCALAPPDATA\Temp\portfolio-browser-check" --no-save --package-lock=false playwright
node docs/check-content.cjs
node docs/check-browser.cjs
node docs/check-audio.cjs
node docs/check-config.cjs
node docs/check-links.cjs
node docs/check-live-media.cjs
```

`PLAYWRIGHT_PATH` задаёт другой путь к Playwright, `PORTFOLIO_URL` — другой адрес сервера. `check-content` сравнивает исходные ссылки, роли и изображения; при последующем намеренном изменении этих материалов нужно обновить эталон `source-inventory.json`. Эта проверка также проверяет уникальность ID эффектов, переводы категорий и наличие файлов по указанным путям.

В layout-тесте проверяются обе локализации на 14 ширинах 320–1920 px; внешние виджеты перехватываются. `check-live-media` отдельно проверяет реальные SoundCloud и YouTube. `check-audio` сначала проверяет реальные SFX из текущих данных: загрузку, воспроизведение, паузу, перемотку и EN/RU. Затем проверяет ошибки и координацию плееров на WAV в памяти перехваченных запросов; тестовые звуки не публикуются. `check-config` проверяет девять вариантов настройки шоурила. Скриншоты: `%LOCALAPPDATA%/Temp/portfolio-browser-check/screenshots`. Результаты текущей проверки: `docs/redesign-audit.md`.
